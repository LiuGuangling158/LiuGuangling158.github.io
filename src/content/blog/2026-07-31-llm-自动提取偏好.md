## 一、从对话到画像——自动化提取

Day 13 讲到会话结束时生成对话摘要。今天的关键问题是：**如何从摘要中自动化提取用户偏好？**

方法：让 LLM 做这件事。

```python
PREFERENCE_EXTRACTION_PROMPT = """从以下对话记录中提取用户偏好。

## 提取维度
1. instance_preference — 产品/实例偏好（使用什么型号、关注什么特性）
2. tech_stack — 技术栈（技术背景、使用的工具）
3. business_scenario — 业务场景（行业、规模、使用目的）
4. budget_preference — 预算偏好（敏感度、价格区间、计费模式偏好）

## 提取规则
- 只提取明确的信息，不要推测
- 为每条标注置信度（0.0-1.0）
- 附上对话中的具体证据
- 生成去重键（dedup_key）

## 对话记录
{conversation}

## 输出 JSON
{"preferences": [{"type": "...", "content": "...", "confidence": 0.9,
  "evidence": "...", "dedup_key": "..."}]}
"""
```

**举例**——从以下对话：
```
用户：我是电商运维，主要用 C7.4xlarge 跑 Web 服务，对延迟很敏感
```

LLM 提取：
```json
{
    "type": "instance_preference",
    "content": "用户偏好 C7 系列计算型实例，主要用于 Web 服务，对延迟敏感",
    "confidence": 0.95,
    "evidence": "用户说'主要用 C7.4xlarge 跑 Web 服务，对延迟很敏感'",
    "dedup_key": "instance::C7_series::web_service::latency_sensitive"
}
```

## 二、语义去重——避免偏好"通货膨胀"

同一个偏好被反复提取怎么办？语义去重解决这个问题：

```python
class PreferenceDeduplicator:
    async def is_duplicate(self, user_id: str, new_pref: dict) -> bool:
        # 方法1：dedup_key 精确匹配
        existing = self.collection.query(
            expr=f'user_id == "{user_id}"',
            output_fields=["content"],
            limit=50
        )

        # 方法2：语义相似度匹配
        pref_embedding = await self.embedding.aembed_query(new_pref["content"])
        results = self.collection.search(
            data=[pref_embedding],
            anns_field="preference_embedding",
            param={"metric_type": "COSINE", "params": {"nprobe": 16}},
            limit=3,
            expr=f'user_id == "{user_id}"'
        )

        if results and len(results[0]) > 0:
            if results[0][0].score > 0.85:  # 相似度 > 85% → 重复
                return True
        return False
```

**重复时不新增，而是提高已有偏好的置信度**：
```python
new_confidence = old_confidence * 0.6 + new_pref["confidence"] * 0.4
```

这样，被多次提到的偏好置信度逐渐升高，偶然提及的偏好置信度自然较低。

## 三、新会话的上下文注入

长期记忆的价值在新会话启动时体现——将用户偏好注入 System Prompt：

```python
async def build_system_prompt_with_memory(base_prompt, user_id, memory, query=None):
    memory_context = await memory.get_user_context(user_id, query)

    if memory_context["has_memory"]:
        return base_prompt + f"""
## 用户画像（基于历史对话）
{memory_context['context_text']}

重要提示：
1. 优先推荐符合用户偏好的产品和方案
2. 如果用户当前问题与已知偏好冲突，以当前表述为准
3. 自然地运用这些信息，不要暴露"根据你的历史记录"
"""
    else:
        return base_prompt + "\n这是你与这位用户的第一次交互，请在对话中了解用户需求。"
```

**效果**：新会话首条消息，Agent 就已经"知道"用户的行业、技术栈、产品偏好——无需用户重复。

## 四、记忆生命周期管理

```python
class MemoryLifecycle:
    async def confidence_decay(self):
        """90 天未更新的偏好，置信度降低 20%"""
        cutoff = int(time.time()) - 90 * 24 * 3600
        old = self.collection.query(
            expr=f"last_updated < {cutoff} && is_active == true",
            output_fields=["id", "confidence"]
        )
        for pref in old:
            self.collection.upsert([{
                "id": pref["id"],
                "confidence": pref["confidence"] * 0.8
            }])

    async def deactivate_low_confidence(self):
        """停用置信度 < 0.3 的偏好"""
        self.collection.delete("confidence < 0.3 && is_active == true")
```

**设计哲学**：记忆不需要"永久精准"——过时的偏好（用户换了实例型号、改了技术栈）自动衰减并被淘汰，让画像始终反映用户当前状态。

## 核心要点

1. **LLM 自动提取偏好是记忆系统的核心创新**——用户无需填表，从自然对话中自动学习；
2. **语义去重避免偏好"通货膨胀"**——同一偏好反复提取是强化而非重复存入；
3. **置信度衰减让记忆保持"新鲜"**——过时偏好自动淘汰，不需要人工维护。
