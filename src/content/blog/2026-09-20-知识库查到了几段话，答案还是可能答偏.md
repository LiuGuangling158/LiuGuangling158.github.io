# 知识库查到了几段话，答案还是可能答偏

> **系列**：MewHelp Agent 踩坑日志
> **关键词**：RAG、混合检索、重排、证据检查

## 一、一句话里，可能问了三件事

项目检索代码里有这样一个例子：

```text
我在新疆下单 80 块钱，运费怎么算，会员的免运费能不能抵？
```

这里同时涉及地区、金额和会员权益。整句话拿去做向量检索，结果可能主要围绕“会员免运费”，偏远地区的限制条款却没排进来。

如果直接把这些结果交给模型，它仍然能写出一段完整回答。问题在于，缺的那条规则可能被它自己补上了。

只检查“有没有召回结果”，很难发现这种错误。需要继续看：用户问到的条件，在材料里有没有交代。

## 二、先处理漏检，再决定能不能回答

MewHelp 的知识分支会先检索，再进入生成节点。默认使用向量与 BM25 混合召回，之后重排。

对于能按标点拆成多个子句的问题，检索器会分别查，再轮流合并结果。这样可以给不同诉求留出位置，减少前几条全是同一类材料的情况。

但拆得更细也会带来噪声。`retrieval.py` 的注释记录过：拆分配合重排有改善，其他几种策略反而下降。所以这里没有“多拆几句总会更准”这种保证，还是要看评估结果。

合并之后，还有两次检查：

```text
混合召回 → 重排
              ↓
         证据分数够不够？
              ↓
         材料能不能回答这句话？
              ↓
         带引用生成 / 证据不足时兜底
```

## 三、分数和语义分别检查

第一步算证据分数。项目使用重排第一名得分、有效证据数量、前两名分差，以及关键条款命中情况，算出一个加权结果。

知识节点里的关键分支如下，省略了日志和其他返回字段：

```python
conf = compute_evidence_confidence(hits)

if conf.score < settings.evidence_confidence_threshold:
    return {
        "evidence_strong": False,
        "fallback_source": "retrieval_low_conf",
    }
```

当前默认阈值是 `0.26`。它对应本项目的评分方式和校准数据，不能理解成答案有 26% 的正确率。换一套资料或重排模型后，这个数要重新验证。

分数过线后，还会把问题和材料交给 `selfcheck.check_sufficient()`，判断材料是否足够。

例如三段材料都在介绍会员权益，得分可能不错，但用户真正关心的是“新疆是否适用”。数值检查很难单独判断这种缺口，所以还需要这一层语义判断。

只有通过检查，材料才会被编号后交给 Agent。提示词要求关键结论带引用，涉及条件的地方把条件一起说出来。

## 四、出错时，要能找回当时给了模型什么

最终回答不够用来排查 RAG。看到一句错误的运费说明，还分不清是没检索到、排序靠后，还是模型拿到了却没用对。

项目因此保留前三条召回材料的快照，包括原文、重排分数和章节路径。

证据不够时，快照跟着问题进入低置信度问题池。证据通过检查后，也会留在本轮状态里，供后续差评回查。问题池另外区分 `retrieval_low_conf` 和 `self_check`，避免把两种失败混在一起。

这一步没有直接提高回答分数，但让后续修改有了依据。缺政策就补资料；已经检到了却答错，就检查证据组装和生成过程。

## 核心要点

验收知识问答时，多用带条件的问题。别只看回答流不流畅，也要对照它引用的那几段材料，看金额、地区、例外条款有没有被遗漏。
